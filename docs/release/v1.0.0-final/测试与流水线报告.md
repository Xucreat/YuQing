## 1. 测试基础设施

- 框架：pytest（Python 3.13.14），后端 venv `backend/.venv`。
- 夹具：`tests/conftest.py` 在导入期强制 `DATABASE_URL` 指向隔离测试库 `opinion_test@:5433`，并对非测试目标抛错。
- 测试库为独立 PostgreSQL cluster，与生产 `opinion_db@:5432` 物理隔离。

## 2. 本次修复：collection 挂起

**现象**：`pytest --collect-only tests` 在全量窗口内（>90s）未返回，进程需强制终止。

**定位（二分法）**：
- 按文件分批收集，确认仅 `tests/test_rbac_hardening.py` 在 collection（导入）阶段挂起。
- 通过 `sys._current_frames()` 定时器栈转储定位到模块级 `DYNAMIC_ROLES = _db_roles()` → `db.query(Role)`，在导入期对 `opinion_test@:5433` 发起连接；本环境该测试库未启动，TCP 连接无限阻塞。

**根因**：该模块在 import 期直接 `SessionLocal()` 连接由 conftest 设定的测试库；当隔离测试库不存在时，socket 连接无超时，导致 collection 永久挂起。属**环境相关**问题（缺测试库），非生产写入。

**修复（测试基础设施-only）**：
- 守卫 `_target_db_is_production()`：仅依据当前生效 `DATABASE_URL`/engine 绑定地址判断；若为生产库 `opinion_db` 则模块级 `pytest.skip`。已移除原先回退读取 `.env` 的逻辑（避免 conftest 已重定向至测试库时被误判为生产库而跳过）。
- `_db_roles()` 改用独立 engine 并加 `connect_timeout=5`；测试库不可达时抛出 `OperationalError`，被模块级 `try/except` 捕获并降级为 `DYNAMIC_ROLES = []`，动态角色用例自动 skip。

**验证**：
- 单文件 `pytest --collect-only tests/test_rbac_hardening.py`：正常返回，不再挂起。
- 全量 `pytest --collect-only tests`：收集 **1521** 个用例，0 错误，0 挂起。
- 未对生产库执行任何测试用例（满足隔离约束）。

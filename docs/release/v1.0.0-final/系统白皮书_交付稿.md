## 1. 系统定位

舆情监测系统（项目代号 YQ）是一套面向政务/企业舆情态势感知的采集、治理、分析与预警平台。系统对境内外多源信息进行采集，经过去重、风险研判、事件归并与告警评估，形成可交互的 Dashboard、舆情列表、事件中心、预警中心与系统管理界面，支撑值班与指挥场景。

## 2. 总体架构

```
[数据源] --采集--> [后端采集服务] --写入--> [PostgreSQL opinion_db]
                                               |
                              [FastAPI 后端 API :8000] <--> [Vue3 前端（build 后由后端 static 托管）]
                                               |
                              [APScheduler 调度]  [RBAC 鉴权]  [Alembic 迁移]
```

- **后端**：FastAPI 0.115.0 + Uvicorn 0.30.6，SQLAlchemy 2.0.35（ORM），Pydantic 2.9.2（校验），psycopg 3（驱动），bcrypt 4.2.0（口令哈希），APScheduler 3.10.4（调度），Alembic 1.13.2（迁移）。
- **前端**：Vue 3.5.12 + Vite 5.4.10 + TypeScript 5.6.3 + Element Plus 2.8.4 + Pinia 2.2.4。生产构建产物 `frontend/dist` 经后端 `backend/app/static` 托管，访问入口与 API 同源。
- **数据库**：PostgreSQL 16，库名 `opinion_db`，实例 `127.0.0.1:5432`，`system_identifier = 7663057120701798896`。共 50 张业务表。
- **鉴权**：JWT Bearer + RBAC 角色权限矩阵；权限码 89 个，角色 5 个，角色-权限关联 131 条。

## 3. 核心能力

| 域 | 能力 | 说明 |
|---|---|---|
| 采集 | 多源采集（境内/外） | 通过 `data_sources` 配置化驱动，支持调度与手动采集，任务去重与 409 冲突保护 |
| 治理 | 去重 / 游标 | `keyword_cursor` 等机制控制增量采集边界 |
| 研判 | 风险模型 | 风险评分与统计，支撑待处理项展示 |
| 事件 | 事件中心 | 舆情归并为事件，支持状态流转 |
| 预警 | 统一预警中心 | 境内告警、外网告警、外网告警规则三类标签页 |
| 权限 | RBAC 收口 | 角色/权限矩阵化，超管与受限角色分离 |
| 运营 | Dashboard | 态势总览、统计、导航 |

## 5. 运行入口

- 后端：`uvicorn app.main:app --host 0.0.0.0 --port 8000`；`/health` 返回 `200`（含 `collector_discovery=db_driven`）。
- 前端：生产态由后端静态托管，开发态 `vite` 监听 5173（默认不启用）。
- 容器端口约定见 `docker-compose.yml`（8080）。

## 6. 交付边界与已知限制

- 本交付为 **代码与文档冻结基线**，不含生产环境部署迁移执行。
- 完整自动化测试需独立隔离测试库 `opinion_test@:5433`（由 `tests/conftest.py` 强制），本冻结环境未启动该库，故仅完成 collection 验证（见测试与流水线报告）。
- 当前 `data_sources` 全部为未启用状态，运行期无活跃采集任务（与 `collector_runs.running = 0` 一致）。
- 详细遗留项见《遗留问题清单_v1.0.0.md》。

> 版本：v1.0　编制日期：2026-07-30　状态：待评审（本文档只做设计，未改动任何代码）

## 0. 需求与已确认的决策

**原始需求**

1. 点击「导出舆情报告」弹出**右侧弹窗**，可设置：报告名称、导出时间（采集时间 / 发布时间）、报告类型（即时 / 定时，定时需设发送时间）、发送途径（邮箱 / 直接下载）。
2. 报告模块可**自定义增删**。

**已确认决策（本次澄清结果）**

| 决策项 | 结论 |
| --- | --- |
| 定时报告语义 | **周期订阅**（每日 / 每周 / 每月 + 时间点），任务持久化、持续生效 |
| 邮件通道 | **标准 SMTP**，配置项先落地（config.py + .env），真实账号后续提供；开发期用 dry-run + 本地假 SMTP 验证 |
| 模块配置粒度 | **本次生效 + 可另存为报告模板**（模板可复用、可被定时任务引用） |
| 导出格式 | **仅 PDF**（沿用 reportlab，把现有固定章节重构为可插拔模块） |

**零新增依赖**：SMTP 用标准库 `smtplib`/`email`；定时下次触发时间复用已装的 APScheduler `CronTrigger`；前端模块排序用按钮上下移，不引入拖拽库。

## 3. 报告模块注册表（核心重构）

在 `report_service.py` 中把 6 个硬编码章节拆成**模块注册表**，每个模块 = `{key, name, 数据构造器, PDF 渲染器, 默认参数}`。渲染时按用户提交的 `modules` 数组顺序执行，章节序号（一、二、三…）动态生成。

| # | key | 模块名 | 来源 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | `overview_kpi` | 总体态势 KPI | 现章节一 | 默认开 |
| 2 | `trend` | 舆情趋势 | 现章节二 | 默认开，参数 `days` |
| 3 | `sentiment` | 情感分布 | 现章节六 | 默认开 |
| 4 | `top_risky` | 高风险舆情 TOP | 现章节三 | 默认开，参数 `top_n` |
| 5 | `events` | 重点事件 | 现章节四 | 默认开，参数 `top_n` |
| 6 | `source_dist` | 来源分布 TOP | 现章节五拆分 | 默认开，参数 `top_n` |
| 7 | `region_dist` | 地区分布 TOP | 现章节五拆分 | 默认开，参数 `top_n` |
| 8 | `keyword_dist` | 热点关键词 TOP | 现章节五拆分 | 默认开，参数 `top_n` |
| 9 | `risk_category` | 风险分类分布 | **新增**，用 `opinions.risk_category`（Phase2-B.2 已落地） | 默认关 |
| 10 | `alert_summary` | 预警处置概览 | **新增**，用 `alert_records.status` 五态统计 | 默认关 |
| 11 | `opinion_list` | 舆情明细清单 | **新增**，按时间倒序，参数 `limit`（上限 200） | 默认关 |
| 12 | `conclusion` | 结论与建议 | **新增**，规则化文本（风险率/负面率阈值触发话术） | 默认关 |

> 现章节五「分布特征」的三合一表格拆成 3 个独立模块，是本次唯一破坏性 UI 变化（PDF 版式变化，非数据变化）。

**关键约束**：模块渲染器必须**互相独立、失败隔离**——单个模块抛异常时记录该模块渲染失败并继续输出其余模块，而不是整份报告 500。

## 4. 时间口径改造（最高风险项，需先摸底）

现状 `get_dashboard_stats(db, days)` 内部所有查询都写死 `cast(Opinion.created_at, Date) >= window_start`。改造有两条路：

- **方案 A（推荐）**：给 `dashboard_service` 增加**可选参数** `start_date` / `end_date` / `time_field='created_at'`，内部抽取 `_time_col(time_field)` 与 `_time_filter()` 两个私有辅助函数统一替换。默认调用行为**完全不变**，驾驶舱本身零回归。
- 方案 B：另起 `report_data_service` 独立实现。回归面为零但重复代码多、双份口径易漂移。**不采用**。

**必须先做的数据摸底（Phase 0）**：统计 `publish_time IS NULL` 的占比。

```sql
SELECT count(*) AS total,
       count(*) FILTER (WHERE publish_time IS NULL) AS null_publish
FROM opinions;
```

- 若空值率低（< 5%）：按发布时间统计时**严格过滤**（NULL 不计入），PDF 页脚注明「按发布时间统计，缺失发布时间的 N 条未计入」。
- 若空值率高：改为 `COALESCE(publish_time, created_at)`，页脚注明回退口径。

**时区**：库内 `created_at` 存 UTC（`datetime.now(timezone.utc)`），而用户在弹窗里选的日期与发送时间是本地时间（Asia/Shanghai，UTC+8）。必须在 API 入口统一做本地日期 → UTC 区间的换算，否则每天早 8 点前的数据会归错日期。这是最容易出线上问题的点，需单独写单测。

**请求体 Schema**（`backend/app/schemas/report.py` 扩展）

```python
class ReportModuleCfg(BaseModel):
    key: str
    params: dict = {}

class ReportExportRequest(BaseModel):
    name: str = Field(max_length=120)
    time_field: Literal["created_at", "publish_time"] = "created_at"
    range_type: Literal["last_n_days", "custom"] = "last_n_days"
    range_days: int | None = Field(default=7, ge=1, le=365)   # 放开现有 7~30 限制
    start_date: date | None = None
    end_date: date | None = None
    modules: list[ReportModuleCfg]                             # 顺序即章节顺序
    delivery: Literal["download", "email"] = "download"
    recipients: list[EmailStr] = []                            # delivery=email 时必填且非空
    save_as_template: bool = False
    template_name: str | None = None
```

校验规则：`range_type=custom` 时 `start_date <= end_date` 且跨度 ≤ 365 天；`delivery=email` 时 `recipients` 非空；`modules` 非空且 key 必须在注册表内、不可重复。

## 7. 邮件服务

新建 `backend/app/services/mail_service.py`（标准库实现，无新依赖）：

- `send_mail(to: list[str], subject: str, body: str, attachments: list[tuple[str, bytes]])`
- 支持 SSL(465) / STARTTLS(587) / 明文，按端口与配置自动选择
- 中文文件名附件用 RFC 2231 编码（`email.headerregistry` / `Header`），避免收件端乱码
- 超时 20s，失败重试 2 次（指数退避），最终失败写 `report_records.error_message`
- **dry-run 模式**：`SMTP_ENABLED=false` 时不真实发信，只记录日志并把 PDF 落盘，供联调期使用

`backend/app/core/config.py` 新增配置项（对应 `.env` 大写键）：

```
SMTP_ENABLED=false
SMTP_HOST=
SMTP_PORT=465
SMTP_USER=
SMTP_PASSWORD=
SMTP_FROM=            # 发件人显示地址，通常与 SMTP_USER 一致
SMTP_USE_SSL=true
SMTP_SENDER_NAME=舆情监测平台
REPORT_STORAGE_DIR=app/storage/reports
```

> 🔐 `SMTP_PASSWORD` 只写 `.env`（已在 .gitignore），`.env.example` 里留空占位。绝不提交真实授权码。

## 8. 定时调度设计

**不采用**「每个任务动态注册一个 APScheduler job」，而用**轮询 tick**，理由：任务存库、支持热增删改、双 uvicorn（8000/8011）实例下靠已有 advisory lock 天然只有一个进程在跑。

- 在 `scheduler.py` 新增 `_run_report_dispatch_job()`，`IntervalTrigger(minutes=1)`，id=`report_dispatch`，受新配置 `report_schedule_enabled` 控制（默认 true）。
- 每次 tick：
  ```sql
  SELECT * FROM report_tasks
  WHERE enabled = true AND next_run_at <= now()
  ORDER BY next_run_at
  LIMIT 10
  FOR UPDATE SKIP LOCKED;
  ```
  `FOR UPDATE SKIP LOCKED` 做并发兜底（即便未来多实例都跑调度也不会重复发信）。
- 执行：构造 config → 生成 PDF → 落盘 → 发邮件 → 写 `report_records` → 更新 `last_run_at/last_status` → 用 APScheduler `CronTrigger(...).get_next_fire_time()` 算出新的 `next_run_at`（**不做补发**：错过的周期直接跳到下一个未来时间点，避免服务重启后雪崩式补发历史报告）。
- 单任务异常必须捕获，不能让一个坏任务打断整个 tick。

**时区**：`next_run_at` 存 UTC，计算时用任务自身 `timezone` 字段的本地时间构造 cron，再转 UTC 落库。

## 12. 风险与规避

| 风险 | 等级 | 规避 |
| --- | --- | --- |
| 改 `dashboard_service` 影响驾驶舱本身 | 高 | 只加**可选参数**，默认行为不变；改动后先回归驾驶舱全部图表 |
| 时区导致日期归属错误 | 高 | API 层统一本地→UTC 转换 + 专项单测；跨 0 点数据人工核对 |
| `publish_time` 大量为空导致报告数据「凭空变少」 | 中 | P0 先摸底；页脚显式标注口径与排除条数 |
| 生产库误操作 | 高 | 迁移前强制 `scripts/db_identity_check.py`（退出码 0 才继续）；测试用 `:5432/opinion_test` + `DB_IDENTITY_CHECK=off` |
| SMTP 凭据泄漏 | 高 | 只入 `.env`，`.env.example` 留空；日志脱敏，不打印密码 |
| 定时任务重复发信 | 中 | advisory lock + `FOR UPDATE SKIP LOCKED` 双保险；不做错过补发 |
| PDF 文件堆积占盘 | 低 | 落盘按月分目录；加一条清理策略（保留 90 天），或定时报告只发邮件不落盘（可选） |
| 前端构建 OOM | 中 | 已知坑：必须 `node.exe --max-old-space-size=1400 node_modules/vite/bin/vite.js build`（cwd=frontend），构建前先停一个 uvicorn 释放内存 |
| 后端改动未生效 | 中 | 已知坑：改 backend 必须重启 uvicorn（`taskkill /F /PID` → 后台重启），并比对文件 LastWriteTime 确认新代码加载 |

**回滚**：每阶段独立 revision，`alembic downgrade` 逐级回退；前端保留旧 `downloadReport` 逻辑在 git 历史中，必要时抽屉入口一行开关即可回退到旧行为。

## 13. 需要你提供 / 拍板的信息

1. **SMTP 账号**：服务商（企业微信邮箱 / QQ / 163 / 自建 Exchange）、host、port、账号、授权码、发件人显示名。未提供前 P4 只能 dry-run。
2. **默认收件人**：定时任务是否需要「发给某角色下所有用户邮箱」这种能力，还是只手填邮箱？（当前设计为只手填）
3. **模块清单确认**：第 3 节 12 个模块是否有需要增删的？尤其新增的「舆情明细清单」「结论与建议」是否要做。

5. **历史报告留存**：是否需要「历史报告」列表页支持重新下载？（影响是否必须落盘）

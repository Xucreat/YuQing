## 4. 发现的问题（仅记录，未修复）

### F1 ｜ 低 ｜ db_identity_check 在"有意重置后"误报 MISMATCH
- 现象：`opinions ≥ 100` 业务指纹阈值未达（当前 83），工具退出码 2 / ABORTED。
- 影响：仅影响该安全工具的自动化判定；system_identifier / database / alembic 三信号均确认是真实生产库。
- 建议（供后续拍板，非本次范围）：在"已初始化新周期"场景下，将业务指纹阈值下调（如 ≥20）或改为"仅校验 system_identifier + database 名"，避免重置后误杀合法写操作。
- 本次处理：**未修改**该工具。

### F2 ｜ 中 ｜ 舆情详情 modal 的"AI 分析"结构化面板读取 `ai_*` 列，导致风险评分恒显 0
- 现象：`OpinionDetailModal.vue` 行 113-117 的"风险评分/级别/情感"读 `detail.ai_risk_score` / `detail.ai_sentiment`；而自动采集写入的是 `risk_score`(20-100) / `sentiment`，`ai_risk_score` 恒为 0、`ai_sentiment` 恒为 neutral（DeepSeek 手动触发才填）。
- 结果：modal 的 AI 分析面板对**所有**舆情显示风险分 0 / 级别 low / 情感 neutral，与列表或 `risk_score` 实际值不一致；只有当用户手动"触发 AI 分析"并完成后，`ai_*` 才被填充。
- 影响：展示一致性（非数据完整性），与廊坊切换无关，为既有设计特征。
- 建议（供后续，非本次范围）：统一 modal 风险展示字段来源（或直接读 `risk_score`/`sentiment` 兜底）。
- 本次处理：**未修改**前端。

### F3 ｜ 低 ｜ collector_runs.trigger_type 列 VARCHAR(16) 长度偏紧
- 现象：本次验收采集用 `trigger_type="acceptance_verify"`(16 字符) 触发 `value too long for type character varying(16)`，改用 `"manual"` 后正常。
- 影响：真实系统仅用 `"scheduled"`(9)/`"manual"`(6)，当前无碍；若未来引入更长触发类型会失败。
- 建议（供后续）：扩至 VARCHAR(32) 或约束触发类型枚举。
- 本次处理：**未修改**表结构。

### F4 ｜ 信息 ｜ 廊坊下辖部分区域码暂未出现舆情
- 现状：opinions 区域分布仅含 131000/131028/131024；**131022(固安) / 131082(三河)** 暂未匹配到内容（属正常——取决于实际新闻命中，码本身在允许集内）。
- 影响：无。一旦采集命中，数据将归入对应廊坊区县码。
